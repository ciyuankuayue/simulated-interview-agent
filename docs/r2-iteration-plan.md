## 2. 逐项考量

### T0 — 工程加固（先稳后迭代，用户指定优先）

#### C1 并发压测实证额度不超发
- **难度**：中。**必要性**：高（业务级产品，计费错误=资损/信任崩）。
- **初始方案**：`billing/QuotaService` 扣减已是条件 UPDATE + REQUIRES_NEW 事务（domain 已声明但未实证）。补并发测试：N 线程同时对同一用户配额扣减，断言 `used_tokens ≤ total`、无负余额、无超发；可先用 JVM 并发单测/JMeter，不引入 Redis（domain 明确不引）。
- **验收要点**：压测（如 50 并发 × 多次）下零超发；用例进 `mvnw test` 全绿。
- **依赖**：无。

#### C2 安全审计（JWT≥32B / 日志脱敏 / 密钥不落 git）
- **难度**：低–中。**必要性**：高（上线必备）。
- **初始方案**：静态核查 + 测试双保险——① `JWT_SECRET` 生产 <32B 启动失败/WARN；② AOP/日志层脱敏，token/password/key 不落盘明文，SSE `?jwt=` 不写日志；③ 全仓扫描无硬编码密钥；④ BYOK AES-GCM 密钥 `APP_DATA_KEY` 仅 env。
- **验收要点**：安全核查清单全过；测试覆盖密钥长度门槛与日志脱敏断言。
- **依赖**：无。

#### C3 Lucene 索引健康检查 + 孤儿块回收
- **难度**：中。**必要性**：中高（配合 F4 删除接口上线前必须，否则孤儿块累积）。
- **初始方案**：扩展 `StartupIndexCleaner`——新增「源表行存在但向量多余」检测（**先告警不自动删**，防误删）；提供 admin 触发 `deleteBySource` 的运维端点/脚本；维度不一致已抛异常（保留）。
- **验收要点**：孤儿块检测有日志/端点；与 F4 删除→清向量联动测试通过（AND 语义删除，严禁 OR）。
- **依赖**：F4。

### T2 — P1 产品脊柱（业务级差异化，核心设计）

> 设计骨架见对话中域模型图。四个待拍板决策 D1–D4 见 §3。

#### B1 `exam_track` 总纲 + `jd_profile` 退化
- **难度**：中。**必要性**：高（产品脊柱，业务级定位）。
- **初始方案**：新增 `exam_track` 表（code/name/description/flow_template_ref/status），seed 三 track（考公/考研/求职）；`interview_session` 加 `track_id`；求职 track 仍关联 `jd_profile`，其他 track 弱化 JD。`GET /api/tracks` 列表。
- **验收要点**：三 track 可建可选；session 正确关联；原求职流程零回归。
- **依赖**：无。

#### B2 `flow_template` 流程配置驱动
- **难度**：高（编排层重构，从硬编码三角色→配置）。**必要性**：高（不同面试流程是核心差异）。
- **初始方案**：`flow_template` 定义 stages（每 stage = 出题官类型/题型/轮次/是否追问）；编排器读 track 的 flow_template 生成题目序列，替代现有 `roles` 轮转逻辑；求职 track 的 flow_template **还原 R7 三角色行为**，保证向后兼容。
- **验收要点**：求职 track 行为与 R7 一致；考公/考研 track 按各自流程出题；新增 track 仅改配置不碰代码。
- **依赖**：B1。

#### B3 `question_bank` 系统面试题库 + RAG blend
- **难度**：中–高。**必要性**：高（平台权威性来源，不只靠用户资料）。
- **初始方案**：`question_bank` 表（track_id/question_type/content/reference_answer/difficulty/tags）；seed SQL 预置各 track 面试题；ingest 以 `userId=SYSTEM` 写入 Lucene（复用现有向量存储与 pre-filter）；`RagService` 检索时 **blend SYSTEM + 当前用户**；出题 LLM 提示词注入系统题库上下文。
- **验收要点**：无用户资料时仍能基于系统题库出题；用户/系统资料隔离正确；预置题库可检索命中。
- **依赖**：B1；C3（防孤儿块）。

### T3 — 体验（Vue 首批组件，避免 Thymeleaf 做两遍）

#### U1 错题本点击展开
- **难度**：低。**必要性**：高（用户痛点）。
- **初始方案**：Vue 组件基于已有 `GET /api/weak-point/{id}` 详情做折叠展开；处理 `latest=null`/`review=null` 降级态。
- **验收要点**：点击展开显示最近答崩现场 + Critic 纠正/补充/示范；降级态不崩。
- **依赖**：A3。

#### U2 报告 Markdown 导出
- **难度**：低。**必要性**：高（用户痛点）。
- **初始方案**：后端新增 report 的 `.md` 文本端点（或前端拼 Markdown 下载）；**零依赖优先 Markdown**，PDF 作后续增强。
- **验收要点**：报告可下载为 `.md`，含逐轮讲解/纠正/补充/示范/匹配度。
- **依赖**：A3。

#### U3 资料上传框 UI 优化
- **难度**：低。**必要性**：中高。
- **初始方案**：Vue 组件做拖拽上传/进度/多文件（JD/resume/note/project_doc/real_record 各入口）。
- **验收要点**：上传体验顺滑；与现有 POST 接口对接无误。
- **依赖**：A3。

### T4 — 功能扩展

#### F1 智能复习组卷
- **难度**：中。**必要性**：高（比通用模拟更提分）。
- **初始方案**：基于 `weak_point`（due + 未出队）自动生成专项 session；复用现有 engine，`start` 增加 "review mode" 只取薄弱知识点组题。
- **验收要点**：生成只练薄弱点的场；答崩继续入队、答对出队。
- **依赖**：B1（track 维度组卷）。

#### F2 单题重练 / 回放
- **难度**：中。**必要性**：中高。
- **初始方案**：新增「重练某轮」入口，复用该主问题+追问链，对比前后 score。
- **验收要点**：重练后显示前后分差；不污染原 report。
- **依赖**：B1。

#### F3 错题主动复习模式
- **难度**：中。**必要性**：中。
- **初始方案**：基于 `GET /api/weak-point/due` 的独立复习会话（区别于整场面试）。
- **验收要点**：due 知识点可单独练；与 F1 边界需明确（可能合并）。
- **依赖**：B1；与 F1 可能合并，需定边界。

#### F4 资料删除接口 + 向量清理
- **难度**：中。**必要性**：中（工程必须，防孤儿块；上线前必须有）。
- **初始方案**：新增 `DELETE /api/{resume|note|project-doc|real-interview}/{id}`，同步调 `RagService.deleteBySource` 清向量（**AND 语义删除，严禁 OR**）。
- **验收要点**：删除后该源向量不可检索；与 C3 孤儿块回收联动。
- **依赖**：C3。

#### F5 语音 API（TTS + ASR）
- **难度**：中。**必要性**：中（体验增强，非核心）。
- **初始方案**：TTS 朗读题目（前端播放或后端 TTS 端点）；ASR 语音转文本后走现有 `answer` 接口；**复用文本 SSE 管线**，后端可加 TTS 端点或纯前端 TTS。
- **验收要点**：题目可朗读；语音作答等价于文本作答。
- **依赖**：A3。

## 3. 开放决策与风险（待你拍板 / 已知雷区）
