# 小师与小暖体验设计草案

2026-10-24 · 讨论稿；用户已确认默认小测与开启后自动整理画像两项体验，其余实施范围仍待细化；不替代现有 API 契约。

目标：小师帮助用户从听懂走向能回答；小暖回应具体处境，陪用户恢复一点稳定感和行动空间。保持现有 Java / LlmPort / 路由 / 计费体系，优先改善对话质量与等待体验。

## 当前起点

- 两者均为专属提示词、最近 8 轮成功问答、一次 FAST 非思考调用；上下文在内存，重启清空。小师另有 30 分钟闲置清理与同用户并发保护，小暖尚未对齐。
- 不自动读取用户资料、报告或错题，没有持久画像。前端等待完整回复后一次显示，不是真流式。
- 小暖提示词已有具体共情、尊重倾诉、一个可选小步骤等要求；继续堆同类要求不足以证明质量提升，需要多轮样例比较。
- 小暖当前关键词命中即固定回复并清空历史，引用、否定等语境可能误报，关键词也不能覆盖全部风险。

## 小师：围绕一个难点完成小闭环

已确认默认节奏：短解释 → 必要时一个贴切比喻 → 回到原理及比喻边界 → 1–2 个面试考点/问法 → 顺势给一道可跳过的短面试题 → 根据回答纠偏。不是每条消息都重复整套步骤。

- 用户问明确问题时直接开始讲，不先做长问卷；仅在岗位/基础会明显影响答案时问一个必要问题。
- 每次围绕一个主要难点，按用户要求展开代码或细节；比喻用于建立直觉，随后说明对应关系和不能类推的地方。
- 讲解与练习分开呈现：先给问法或练习题，参考答案可在回答后或主动展开时提供，避免把刚展示的答案复读视为掌握。
- 答错先点出已经说对的具体部分，再纠正一个主要误解，换例子或补一个提示后重试；答对可换情境验证迁移。
- 用户说不会、只想看答案、今天不测或想换题时自然调整；用户换话题不强行拉回旧题。
- 短题在一个知识点讲清后自然给出，不要求先点击“考考我”；补充解释、澄清或用户尚未理解时不机械追加新题。跳过、看提示、看答案均可；跳过不计错，“今天不测”在本次对话持续生效，直到用户改变选择。
- 暂用“需要提示／可独立解释／变式待验证”描述本次证据，不凭一次答案写永久能力分数；复用错题体系前需另定写入规则。
- 面试考点按目标岗位组织；没有频次来源就写“面试可能这样问”，不宣称某公司高频。

示例方向：索引可用图书目录建立直觉，再说明查找收益、维护成本及适用条件；问法包括“索引为何可能拖慢写入？”；练习另给一个小场景，待用户回答后反馈。

会话只需保留当前主题、待答题、最近提示和已观察误解等少量信息。首批可利用显式操作和对话窗口；若增加结构化提取，应尽量合并到同次生成，不每轮增加分析、评分、审核的串行调用。

## 小暖：按此刻需要回应

倾听、梳理、一起行动、庆祝进步作为灵活选择，不做必须依次经过的固定流程。可提供“先听我说／帮我理一理／陪我走一步”快捷入口，自由聊天仍为默认。

- 回应用户讲出的具体落差；对可能的感受保留余地，允许用户纠正，不靠猜测隐秘经历制造亲密感。
- 用户只想倾诉时不附加任务；明确求办法时给一个可选小动作，用户拒绝后停止劝做。
- 多轮里跟进新增细节，记得上轮已经尝试或拒绝的建议；说“没帮助”时调整回应，不解释自己为什么正确。
- 鼓励依据用户实际说过或做过的事；报喜就一起高兴，不补写苦难，不保证录用，不把难过都转化成学习任务。
- 温柔主要来自回应准确、节奏合适和尊重选择；称呼、表情及亲密程度遵循用户偏好。
- 普通情绪支持与即时危险另分支处理；改善关键词语境判断并保留保守兜底，不能仅删除关键词护栏。求助资源展示前核实地区与来源，不凭模型编号码。

示例：用户说“准备两个月还是挂了，朋友都拿到 offer 了”，可以回应“准备了两个月还是没等到想要的结果，身边朋友又陆续有了消息，这个落差确实不好受。你说自己不行时，会不会也有一点觉得‘怎么只有我还停在这里’？如果我猜偏了，你可以纠正我。今天不用急着把这次结果解释成对自己的判决。”实际生成不固定复用句式。

## 记忆、知识与工具的取舍

| 内容 | 建议 |
|---|---|
| 共享备考档案 | 用户确认的目标岗位、阶段、可用时间及表达偏好；少量字段，可查看修改删除 |
| 小师学习记录 | 具体题目/知识点、提示情况、回答证据、来源与时间；优先利用现有报告/错题，不另建一套分数 |
| 小暖当次语境 | 当前事件、此刻想倾诉还是求办法、已拒绝的建议；短期保留，不自动固化为人格标签 |
| 小暖长期记忆 | 用户开启记忆后自动整理简短沟通偏好，可查看、修改、删除；情绪原文不默认入资料库或向量库 |
| 小师知识 | 先选一个岗位，以 30–50 张审核卡验证：概念、边界、误解、例子、问法、来源与适用版本；可用项目内 JSON 起步 |
| 已有私有资料 | 用户主动选“结合这份报告／这道错题／这份材料”，服务端验证本人归属，显示来源；小暖不默认共享这些资料 |
| 新外部知识库/搜索 | 首批不必新增服务；确有版本性或资料不足问题时再接入，并展示来源。心理知识库不等于共情能力 |

长期记忆需明确保存范围和保留期；用户可关闭、修改、删除。模型推测不能直接写入已确认事实。公共知识卡与私有 Lucene 数据隔离，保持现有 userId 预过滤与租户约束。

### 已确认的自动记忆方向与建议细则

用户选择“开启记忆后，自动整理可查看、修改和删除的简短画像”。以下细则为此方向的设计建议，尚未实现：

- 首次由用户主动开启，说明保存范围；开启后在范围内自动整理，不逐条弹窗确认。可保留“记住这个／别记这件事”作为用户随时纠正的自然指令。
- 简短画像分成共享备考目标、小师讲解偏好、小暖沟通偏好；详细答题证据留在学习记录中，不把整段历史塞进画像。共享目标不意味着两者可以互读全部聊天。
- 自动保存用户明确表达、适合跨次使用的信息，例如“目标是 Java 后端校招”“先举例再讲原理”“我难过时先别给建议”；每项关联来源和更新时间。未明确说出的性格、病症和原因不自动推断。
- “今天很紧张”“明天面试”“这次不想测试”属于有时效的当次状态，按期限失效；不能长期写成“容易焦虑”“不喜欢测试”。可更新的目标和偏好允许随用户后续明确表达变化。
- 用户手工修改的内容优先；矛盾信息不能无声覆盖手工修订。删除后不能再从旧聊天自动恢复同一项，可提供“不要再自动记录此项”。
- 页面提供记忆开关、记住了什么、逐项编辑/删除与清空全部。建议关闭后停止自动写入，也停止向模型提供已有长期画像；保留内容可查看或另行删除，界面明确二者区别。
- 不为画像每轮额外串行调用模型；可合并提取或低频整理，不挡正文首字。只有校验成功的信息才入库，整理失败不妨碍正常聊天，不虚假提示“已记住”。

## 丝滑体验与工程边界

- 即时显示发送状态；真实模型增量到达才逐段显示。用户向上阅读时不强制拉到底，接近底部才自动跟随。
- 切换小师/小暖或离开页面再返回，保留各自消息、草稿、等待状态；会话清空与长期偏好清空分开说明。
- 小师回复旁提供少量动作：换个比喻、看面试问法、考考我；小暖不用每次回复都弹选项或推动跳转。
- 两者对齐同用户并发、闲置清理、失败保留草稿与真实错误语义；费用不足不能伪装成已完成的回答。
- 真流式需要贯通 Provider → LlmService → 对外传输 → 前端，保留模型路由、用量记账和 402/409 语义；中断、部分回复、重试与用量缺失须设计，不用前端打字动画冒充首字变快。
- 正常闲聊/教学目标为每轮一次模型调用；授权资料读取或确有必要的检索另计成本。用首字耗时、完整耗时、每轮调用数与积分衡量，不先承诺未经实测的响应秒数。
- 新增流式、画像或上下文选择涉及 API/DB 变更，实施前单独确认契约；本草案不授权替换现有接口。

## 建议实施顺序与待讨论项

1. 先拿少量多轮样例共同确定口吻与教学节奏；补对话/草稿切换连续性、并发/清理及语境误报。正常生成保持一次调用。
2. 确认流式契约后实现真实增量显示；针对失败、断线、重试和计费单独验收。
3. 按需求增加可控简短记忆、小师读取选定报告/错题、一个岗位的知识卡；有证据需要更多能力时再扩。

内容验收用自建、独立于提示示例的多轮案例：小师检查事实/比喻边界、考点、纠偏和变式理解；小暖检查具体回应、尊重倾诉、跟进新增细节、纠正后的调整与不过度承诺。同步比较现有 DeepSeek/Qwen 的内容、延迟和积分成本；不能只用提示词单测或模型自评分宣布体验达标。

已确认：小师讲完知识点后默认顺势给一道短面试题，可跳过；跨次记忆由用户开启，开启后自动整理，可查看、修改和删除。仍待细化：自动记忆细则、接口与数据模型、流式失败/计费契约及首批实现范围；确认两项体验不等同于批准所有候选方案。
