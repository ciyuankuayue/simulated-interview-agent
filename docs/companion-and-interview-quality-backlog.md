# 双陪考与面试质量优化清单

2026-10-19 用户反馈：小暖过于机械、安慰不到位；小师解释不通透；模拟问题有偏离实际面试重点的现象。优先改善小暖，再逐步推进教学与知识供给。本文登记后续工作，不代表已经调研开源项目或实现新数据库能力。

## 本批范围

- 内测补额提示：积分不足时说明“平台目前处于内测阶段，请联系工作人员补充额度”，展示工作人员微信 **13481264947**。同时覆盖 HTTP/SSE 错误提示、积分不足弹窗和账号设置；保留草稿，不新增支付接口。
- 小暖第一轮调整：取消强制一两句话；具体回应用户已经说出的事情，按意愿选择倾听或一个小步骤；不强行积极、不机械追问、不重复自我介绍。不把空模型输出伪装成安慰，失败保留输入供重试。
- 保留短期会话、身份隔离、计费收口与危机支持。删除未经核实的硬编码热线号码，后续单独核验专业求助资源。普通倾诉不写入简历或知识库。
- 本批不改小师教学、不引入新框架/模型、不变更数据库结构、不部署线上。

## 小师期望的教学方式（待实现）

1. 根据用户问题和已有基础，用一句容易理解的解释起步，再说明关键机制与适用边界；必要时只问一个基础澄清问题。
2. 列出与目标岗位相符的 2–3 个可能考查点/追问方向；有来源才称高频，否则明确为练习建议。
3. 给一个最小工程情境或短代码例子，讲清输入、执行过程、输出及易错点，不能只贴代码。区分类比和真实机制。
4. 邀请用户用自己的话讲一遍，并给一道小自测；不提前贴出全部自测答案。结合复述指出具体误解，再给一个验证问题，允许用户要求跳过或展开。
5. 调研可借鉴的苏格拉底式导师、teach-back、练习反馈、课程/知识检索项目；以同一组中文面试问题实测，核对官方仓库与许可证、维护成本、是否需额外服务及模型费用。

## 面试资料需要补什么（待采集/设计）

先选一个岗位方向和级别，以小规模、有出处的资料验证，不先大量灌入网页。候选资料：

| 资料 | 作用 | 必须记录/注意 |
|---|---|---|
| 目标 JD 和岗位能力图谱 | 约束题目主题、难度与技能覆盖 | 岗位、级别、技术栈、必需/加分能力、采集日期；区别公司要求和通用要求 |
| 合法来源的真实面经/题目 | 提供实际问法、常见追问与工程侧重 | 来源、日期、岗位级别、可用许可；多来源证据再评估常见程度，不能把模型猜测当频次 |
| 经校验的题目与解析 | 给出题/判分/小师同一份知识依据 | 考点、先修知识、难度、答题要点、常见误解、追问、工程/代码例子；事实和版本经人工核对 |
| 官方文档、原理说明与工程案例 | 校验机制、边界和示例，避免只背题 | 原始链接、适用版本、更新时间、章节、代码语言与运行条件；保留引用 |
| 用户本人简历、真实项目、报告与错题 | 让追问有本人依据，按薄弱点训练 | 用户/租户、来源ID、简历版本、授权范围；绝不编造经历，不混用其他用户或未经选择的版本 |
| 脱敏评测集与相关性标注 | 衡量“是否真的更像面试”，定位退化 | 固定 JD/级别/已学内容、应覆盖考点、偏题样例、人工判断和期望依据；与训练语料区分 |

数据分工建议（尚未实施，需独立评审）：

- 关系数据库保存题目/主题的结构化元数据、岗位级别/版本、来源与许可、难度、审核状态、考查频次的证据、练习及掌握记录。频次缺证据时标“未知”，不用虚构分值。
- 向量库保存按知识点/例子拆分的可引用文本块，携带题目/来源ID、章节、岗位/技术版本等可过滤标记；先按岗位/级别/已选资料约束候选，再检索解释与例子。选题不能仅依赖文本相似度，还要考虑覆盖、去重、先修与本轮追问目标。
- 当前索引按 userId 预过滤。公共知识库与私有资料的 namespace、权限、检索合并和版本更新先设计；不得为接公共题库取消现有租户过滤或借跨租户特权混查。
- 首轮建议人工整理一个岗位的 30–50 道代表题及对应解释/追问，配一组固定 JD 做评测；这是建设建议，当前尚无已收集的数据量或质量结论。

## 小暖验收样例（持续维护）

- “准备两个月还是被拒，觉得自己很差。”：回应投入落空的具体失落，不用保证录用或立刻安排复盘。
- “别给建议，只想抱怨。” → “你还是让我复盘。”：接住修正，停止给任务，不辩解或复读开场。
- “明天面试怕卡壳，有没有一个现在能做的办法？”：给一个具体、可选择的小动作，避免十条清单。
- 用户连续两轮解释不同压力来源：回应新的细节，不复读上一轮，不读取其他人的历史。
- 网络/模型空正文/积分不足：真实显示错误并保留输入，补额展示内测微信；不能伪装成成功安慰。

自动化只验证路由、上下文、错误和隔离，不能证明情绪支持质量。真实模型样例需要人工读，并持续用用户反馈校准。

本批样例复核（合成输入，非真实用户资料）：拒绝后的自我怀疑、纠正“不要建议”、考前请求一个小办法、分享进步共 4 例；发现报喜回复补写了“卡壳和重来”的经历，已补充约束并复测该例，复测未出现此补写。少量样例不能代表总体质量，后续仍优先收集失败样例。原始本地记录 target/warm-quality-samples.json、warm-quality-celebrate-sample.json，不入业务库。
