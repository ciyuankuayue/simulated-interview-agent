## 模拟面试 Agent 业务能力专项（2026-10-20建立 · 全部较高优先级）

来源：2026-10-20 对固定编排的分析及用户将优化点提级的要求。2026-10-21 用户确认优先重构核心决策；本轮授权 Java 内部 Agent 运行时与配套持久化，HTTP/SSE形状保持兼容。以下仍是完整需求与验收，不因首批实现而删除未完成项。

本轮方向：Java 承载共享的面试决策 Agent，以原生工具结果和现场信息决定考什么、追什么、查什么及何时结束；角色按目的选择，不要求每个角色另起无限循环。代码保留权限、计费、题量、追问预算与状态转换控制，不增加框架依赖。旧 NULL 会话保留固定流程兼容。

### 优先级与建议批次

本专项所有条目均为较高优先级：P0 为可信度与可靠性地基，P1 为核心面试能力与训练闭环。此前讨论中能力画像、变式复测与个性化训练属于后续 P2，按本次用户要求提升为 P1，但仍依赖证据与评价能力先落地。批次只表示依赖与实施顺序，不降低其优先级。

| 编号 | 优先级 | 优化项 | 建议批次 / 依赖 |
|---|---|---|---|
| MI-01 | **P0 · 较高** | 本场资料上下文、简历版本与全流程证据链 | 本轮配套快照/有限证据，完整版本策略继续深化 |
| MI-02 | **P1 · 较高** | 岗位考察计划与动态选题 | 本轮主线；结合 MI-01/05 实现首个闭环 |
| MI-03 | **P1 · 较高** | 有诊断目的的追问与停止决策 | 本轮主线；低分/高分不直接决定追问 |
| MI-04 | **P1 · 较高** | 有限只读工具与受约束的行动循环 | 本轮主线；原生工具执行与结果回填 |
| MI-05 | **P0 · 较高** | 证据化评分、不确定性与结构校验 | 本轮配套严格结构/证据上下文，岗位rubric待深化 |
| MI-06 | **P1 · 较高** | 可执行复盘、事实约束与考察覆盖说明 | 本轮配套证据和权威字段，练习效果继续评测 |

### MI-01：本场候选人上下文与证据贯穿（P0）

本轮范围：JD/显式所选简历开场快照，排除其他简历版本；项目/笔记/面经从当前本人索引按需取证并存有限片段，贯穿后续判分/决策/Critic。尚非全资料开场冻结，真实内容验收待评测。

- 开场确定目标 JD、岗位级别、本场选定简历版本、相关项目资料与可见范围。固定本场资料版本或可追溯快照语义，避免切换/更新资料后同场依据漂移；具体存储方式另行设计。
- 上下文记录已确认事实、候选人声明、待核实声明、来源 ID 和对应轮次；简历是声明、回答是现场陈述、文档是补充材料，均不能自动视为已验证事实。
- 后续主问题、追问、判分及 Critic 均按需获得相关证据，补齐当前主要只有首题检索的断点。资料缺失时询问或标未知，不虚构百万并发、性能提升、事故或个人经历。
- 已选简历与其他版本的检索范围需明确；所有检索保留用户/租户隔离，不能通过扩大查询范围混用他人或未经选择的经历。
- **验收**：多版简历互相矛盾、场中更新资料、资料缺失、项目仅有模糊描述等案例下，出题/评分/报告均能追溯本场依据；未知指标只追问、不补写；双账号不能交叉读取。

### MI-02：考察计划与动态选题（P1）

本轮范围：有限 plan 持久化，模型在启用角色中选择 ASK_MAIN/PROBE/CLARIFY/END，代码守住角色/两层/题量/重复题与循环预算。尚无独立岗位能力图谱、严格模拟/训练模式或必考覆盖的确定性证明。

- 根据 JD、级别和材料生成可检查的考察计划，区分必考/加分能力、已覆盖项、证据缺口及剩余预算，不再只靠角色取模确保表面轮转。
- LLM 提议考点和下一步；代码检查岗位范围、重复题、必考项覆盖、题量/时间预算与结束条件。角色按考察目标选择：核实贡献用项目官，冲突沟通用行为官；轮转保留为兜底。
- 提供“严格模拟”和“薄弱点训练”的业务模式设计：前者强调岗位覆盖及现场节奏，后者围绕已有缺口练习；模式与新增字段涉及契约时先评审。
- **验收**：固定 JD 与级别下可解释每次选题目的；不会因机械轮转遗漏必考能力；已掌握项减少重复，薄弱项适度深入，所有决策遵守预算。

### MI-03：诊断式追问与停止（P1）

本轮范围：goal/reason、实际角色、行动与已获取证据随轮次落库；按诊断而非分数阈值选择行动。置信度/缺口类型专门字段、完整回答类型质量评阅仍保留为后续验收。

- 追问依据从单一分数扩展为回答诊断：机制缺失、个人贡献不清、指标缺测量方法、前后矛盾、证据充分、明确不会等。
- 明确不会且缺基础时记录缺口并换题；结论正确但机制不清时追原理；“我们”式贡献追本人工作；性能结论追指标/对照条件；矛盾先澄清；证据充分及时结束，超出预期可在岗位范围内提高难度。
- 结构化输出至少设计评价、下一动作、追问目的、问题、证据轮次和置信度等信息。模型给建议，代码检查合法动作、预算、重复与终止，保留最多两层等现有边界，改变边界需单独确认。
- **验收**：覆盖上述各类回答；低分不机械追满、高分仍可核实依据、明确不会不无效纠缠；问题依赖前文时拿到所需上下文。

### MI-04：有限只读工具与受约束行动（P1）

- 本轮注册 `search_candidate_materials`（本人材料声明）、`get_interview_turns`（无参最近8轮，可选turnSeq读取本场指定轮次）、`get_competency_progress`（plan与轨迹）、`get_scoring_rubric`（当前技术/行为四维与不确定性规则），执行原生工具请求→结果回填→再决策；工具不接受owner参数，完整岗位/级别评分依据仍需建设。
- 面试角色按需获取与职责相关的工具；评估者获取 rubric 与评价证据。若引入自主调用，补齐工具注册、参数/归属校验、执行分发、结果回填、工具错误处理、调用次数/时间/token 预算与终止条件。
- 工具输出区分“未找到”“不可访问”“执行失败”；材料只作数据，不可借材料内容绕过工具权限和编排规则。
- 初期只读；不默认开放扣费、改分、删资料等写工具，业务代码继续控制副作用。不优先加入联网搜索，先使用本人材料与经审核参考库。技术框架选型单独评估，不默认迁移。
- **验收**：回答与项目文档不一致时，能检索并引用后澄清；无检索需求不空转；非法参数/越权/超预算可终止或恢复，不跨租户、不无限循环。

### MI-05：证据化评分与不确定性（P0）

本轮范围：严格评分结构与权威赛道、有限证据上下文、失败null分及Critic权威字段；并未建立所有技术版本的可信参考或独立岗位分级rubric。

- 区分事实错误、回答遗漏、未能核实、上下文不足；没有证明经历或指标，不等于证明经历虚假。结论附当前回答/材料/参考依据，并说明不确定性。
- 按岗位与级别提供可审核 rubric，保留技术和行为赛道。技术事实以适用版本的可信参考为依据；项目评价检查个人贡献、推理和证据，不凭空断言真实性。
- 代码严格校验四维字段、各维 0–2、总分 0–8 且等于维度合计；检查轮次合法性与权威赛道，不能只验证 JSON 能解析。
- 未回答、判分失败或证据不足时使用明确的未评估/不足状态设计，不作为正常低分进入成绩统计；落库/API 表达方式先评审。
- **验收**：维度缺失、越界、合计错误、伪造轮次与模型误标赛道可识别；资料不足不会被判为虚假经历；失败轮次不污染平均分与能力结论。

### MI-06：可执行 Critic 与覆盖范围（P1）

本轮范围：传入已存证据，过滤伪造/重复轮次，恢复原题/评分（含null）/赛道；提示词要求未知事实占位、覆盖与未评估范围、练习/复测建议。内容效果不能由提示词或单测存在直接证明。

- 复盘回答“已获得支持的能力、最影响目标岗位的缺口、下一次练什么及怎样验证改善”，不是重述对话。
- 每个重点缺口关联问题、证据轮次、岗位影响、具体练习和复测方式。例如缓存删除失败问题，要求补画失败路径并解释重试/补偿，再用新故障场景复测。
- 示范回答只能采用已提供的个人事实；未知量级/结果用明确占位符，行为题提供 STAR 骨架，不编造效率提升比例或事故经历。
- JD 匹配度同时说明考察覆盖与未评估范围；少量局部题不能推断完整岗位能力，不把分数包装成录用保证。
- **验收**：报告重点可追溯、练习可执行、复测有标准；没提供的经历/数字不补写；只考缓存与事务时明确其他能力未评估。

### MI-07：分类训练、能力画像与变式复测（P1）

- 错题/缺口区分知识错误、解释不清、项目证据不足、STAR 不完整；分别安排原理与变式题、限时口述、真实贡献/指标整理、行为经历结构补齐。
- 复习换问法或场景验证迁移，不因背熟同一道题就认定掌握。能力变化需要多次、有来源的证据支持，与现有间隔重复规则如何衔接单独设计。
- 按用户、岗位目标、能力维度、时间与证据来源积累画像，记录改善与仍不确定之处；不形成永久标签，不把情绪陪伴记录默认写入能力档案。
- 报告 → 训练 → 变式复测 → 更新能力证据形成个性化闭环；与小师共享上下文必须展示范围并校验本人归属及授权。
- **验收**：同一缺口可进入对应训练；原题背熟但变式失败时不误标掌握；新证据能更新结论，历史依据可回看，跨用户隔离有效。

### MI-08：业务状态、并发与失败恢复（P0）

本轮范围：同场进程guard与hint=0数据库行锁保护answer/end；出题失败保留回答/评分，同文恢复不重新判分，UI已提供“继续生成下一步”及新调用积分提示。answer的402/409业务异常不回滚已保存回答/评分。单实例guard/H2竞争已测，多实例/MySQL NOWAIT未实测；不同数据库可有不同锁异常类型。没有请求ID、短事务或持久任务系统，报告失败单独重试和完整幂等仍待做。

- 服务端保护同一回答的重复提交、并发作答与重复模型调用，不能仅依赖前端禁用按钮或“已作答”先查后写。
- 自动结束与手动结束共用可靠的并发/幂等语义，避免重复报告、重复调用与扣费；已有报告查询不等于并发唯一保证。
- 新题生成失败后有明确可恢复阶段；报告失败可单独重试，不要求重新面试。区分真实成功报告、生成失败和降级内容，不把占位报告永久当作完成。
- 等待时准确区分判分中、出题中、报告中、调用失败。细粒度状态、长事务拆分、异步化与 SSE 的具体方案和契约先评审；与已有性能/SSE专项合并实施，避免两套状态源。
- 明确“重放既有结果”与“重新调用模型”的区别；重连/界面重试不意外触发新调用和额外扣费。新调用、部分失败、缺 usage、取消与重试的结算遵守统一计费收口，保留 402/409 穿透语义。
