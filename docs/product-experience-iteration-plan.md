## 3. 前端目标：围绕一次练习组织页面

- **公开首页**：一句话讲清“按目标岗位追问，给出具体改进”；展示明确标注的示例题与示例报告；主按钮“开始练习”。先浏览价值，开始时登录，不增加匿名模型调用。
- **开始练习**：粘贴/选择 JD → 选择可选简历 → 选 3/5/8 道主问题。简历、笔记、项目资料均不作为开练门槛。提醒主问题之外可能追问，不把 3 题承诺为固定分钟数。
- **面试工作区**：单一主要内容区，突出当前题和回答框；显示角色、主问题/追问进度和真实处理状态；保留上一轮反馈，详细评分折叠。提交失败保留草稿；防重复提交；开始成功自动进入。
- **报告与复习**：先给整体反馈、优先改进点和下一步；逐轮讲解按需展开；复用已有导出、回看、错题重练。报告到达给可见入口，避免强行打断仍在阅读的用户。
- **我的资料**：独立管理简历版本、项目、笔记和真实面经。以“哪些资料会用于面试”解释用途，提供内容预览和处理结果。
- **陪考助手**：持续可达的入口，桌面侧栏/抽屉、手机独立页面；训练建议和情绪陪伴明确分开。
- **账号设置**：额度、用量、模型、BYOK 收进设置，准备页仅保留轻量余额提示。

视觉建议：统一字体层级、间距、按钮与表单；减少边框和无效面板；主操作清晰、题目易读。先做首页、面试、报告三个关键页面的高保真稿，并用真实长文本验版。浅色中性底 + 单一强调色作为首选方向，深色保留为候选，以原型评审定稿。Element Plus 用于基础控件，用户页面仍需自己的排版。

手机是首批验收尺寸，不再排到增强阶段：360/390px 与桌面 1440px 均能读题、输入、提交、看报告；键盘弹起、长文本、空态、加载与错误态一起验证。

## 5. SSE、等待和报告的实施边界

区分三个目标：按钮立即反馈、阶段事件及时到达、模型正文真流式。三者分别验收，打字机动画不能当成性能优化。

1. **测量先行**：记录 request/session/turn 关联、受理、排队、检索、判分、出题、Critic、首个可见内容和结束耗时，以及模型、重试次数、token。内部明细存 DB/结构化日志；页面只显示用户需要的状态。禁止记录 JWT、Key 和完整私密资料。
2. **先修现有事件**：验证订阅重放与发布顺序、终态关闭、断线恢复、TTL 清理；每个 session 同时只执行一个有效写操作。已有数据提交成功后再发布可恢复结果，不能让用户看到随后回滚的题目/分数。
3. **异步受理方案需评审**：answer 可保留 `{accepted:true}` 形状，但 402/409 的出现时点会改变；start 首题和 end 返回完整报告的契约更不能直接改。先在 api.md 写受理/失败/重试/恢复矩阵；再决定兼容端点或版本方案。
4. **实现采用现栈候选**：有界执行器、短事务和每会话互斥；用户/租户上下文先设置再开事务，finally 清理；任务重启后的恢复须有持久状态，不能只靠内存队列。无需为本次目标先引 MQ、WebFlux 或重写 Agent 框架。
5. **模型流式**：优先面试题和陪伴正文；结构化判分继续完整校验。报告可以先展示已有轮次反馈摘要，再展示最终报告；摘要明确为已有反馈，不提前编造总体匹配度。分章节报告只有完整校验后才成为最终持久结果。
6. **延迟优化**：分别约束判分、出题、报告的总时间预算（含重试），避免单次超时叠成数分钟。比较快模型与思考模型的评分质量后再调档；最终下一题依赖本轮分数，不盲目并行。报告 prompt 可复用已有判分细节减少重复分析，不截断必需结论。
7. **流式结算与恢复**：统一走 LlmService/QuotaService；断线不等于取消，重连不重新调用模型。定义完整 usage、缺 usage、主动取消和中途失败的结算口径，确认一次调用只结算一次；流中错误也保留业务码语义。

建议验收目标，均非当前测量结果：点击后 100ms 内有本地反馈；批准异步后受理 P95 <1s；快模型正文首内容 P95 争取 <3s；一轮结果 P95 争取 <15s；完整报告 P95 争取 <45s。固定场长和输入量，DeepSeek/Qwen 分开统计成功/失败/降级与样本量；超过预算展示真实状态及恢复入口。先实测，再锁正式阈值。

## 6. 资料输入与陪考助手

**资料输入分两层**：E1 先让粘贴/已有资料复用顺畅；md/txt 可在浏览器读取后通过现有文本接口提交。E3 再引 PDF/docx 的提取、预览、确认入库与失败反馈；扫描件无文字时明确提示，OCR 按需求增加。新文件接口、删除及向量清理、异步索引状态先评审契约。重试不能重复产生版本或重复扣费，需区分“重新调用模型”和“恢复既有结果”。

资料页面展示名称/类型、版本、当前使用范围、处理状态、预览和管理动作。当前接口没有提供的名称/状态不伪造为持久能力；E1 可先用版本时间与现有字段。resumeId 的语料范围语义在真正修正前明确提示，避免上传多版后混用经历。

**陪考教练**：回答“我现在先练什么”“刚才为什么答不好”，根据本人 JD、已生成报告和错题给一项可执行建议，并链接到原题/重练。没有证据时先询问，禁止编造经历；上下文按需选择并展示来源。现接口仅有 message，新增上下文/模式需评审并在服务端校验归属。

**情绪陪伴**：考前紧张、练习受挫等轻入口，允许暂离面试后返回；不进入严格判分，不自动把情绪内容写进资料库。说明会话保留范围；网络/额度/服务故障给真实原因和重试动作。关键词规则和硬编码求助信息需专业内容复核，不把当前规则当作完整支持能力。

## 7. 推广与验证

可以从小批真实用户开始推广。推广门槛是 E0 核心链路通过、首屏讲清价值、等待可解释、失败可恢复。使用明确标注的演示数据展示报告，不使用真实用户简历、分数或聊天截图充当宣传素材。

每批看同一条漏斗：访问 → 点击开练 → 注册成功 → JD 就绪 → 首答提交 → 完成练习 → 报告查看 → 再练/复习。记录每步成功率、耗时和退出点；先建立基线，不虚构转化目标。按账号统计 7 日再练率、每完成一场的平台 token 成本；首批可做 5–10 位用户走查，收集具体卡点。

回归最小集合：注册登录 → JD → 简历复用 → 开始 → 回答/追问 → 自然/手动结束 → 报告/导出 → 历史/错题；外加模型切换、401/402/409、双账号切换、断线重连。前端接线错误证明仅后端测试通过不够，R5-3 浏览器冒烟提升为每次 UI 发布门槛。

代码批次遵守现有 mvnw 全量回归与人审纪律；工程化后补前端构建与浏览器冒烟。涉及租户/计费/资料持久化时补相应真实依赖验证。发布按可回滚的小批执行，迁移先备份；不自动 commit、合并或部署。
