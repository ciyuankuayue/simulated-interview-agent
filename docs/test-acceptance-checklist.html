测试验收实战清单

先松一口气：验收 ≠ 写测试。 你不用会写 Java 测试代码。验收 = 跑别人写好的测试 + 启动 app 点一遍 + 读改动范围。这三件都不需要你会写代码。

为什么不能只信 AI 说"绿了"

  • AI 可能漏跑测试，只口头说"改好了" → 你自己跑，亲眼看末尾那行数字。
  • 测试可能"假绿"：被跳过（Skipped）或误标通过 → 你看 Failures / Errors / Skipped 三个数。
  • AI 通常只验后端，浏览器没真点过 → 第③步必须你自己点。
  • AI 可能夹带无关改动 → 第④步读 diff 兜底。

四步法

步干啥一句话命令怎么算过
①跑全量测试.\mvnw.cmd -B test末尾 Failures: 0 Errors: 0 BUILD SUCCESS
②启动 app 探活.\mvnw.cmd spring-boot:run浏览器开 /api/health/deps → database.ok:true
③浏览器点一遍 (E2E)开 http://localhost:8080登录→开始→答题→出报告，全程不卡 401
④读 diff 防夹带git diff --stat master...HEAD改动只围绕本 task，无多余重构

① 跑全量测试（最该自己来的一步）

打开终端：用 PowerShell，别用 Git Bash

本机 Git Bash 的 mvn 是坏的，会报 command not found。按 Win 键 → 搜 PowerShell → 回车打开。

切到项目目录

cd C:\Users\19284\WorkBuddy\2026-08-25-17-57-13\simulated-interview-agent

跑测试

.\mvnw.cmd -B test

解释：.\mvnw.cmd 是项目自带的 Maven 包装器（你不用自己装）；-B 批处理模式（输出干净好读）；test = 跑测试阶段。等待约 1–2 分钟，别关窗口。

怎么读结果（看最后几行）

Tests run: 59, Failures: 0, Errors: 0, Skipped: 0, BUILD SUCCESS
看哪个数PASS 信号FAIL 信号
Failures必须是 0非 0 = 有断言没过
Errors必须是 0非 0 = 代码抛异常（比 Failure 更糟）
Skipped0（本次是 0）非 0 = 有测试被跳过，问 AI 为啥跳
末尾BUILD SUCCESSBUILD FAILURE = 编译或测试挂了
总数 59和预期一致突然变少 = 可能测试被砍/跳
关键： 你判断"绿"的标准是你亲手跑出来这行字，不是 AI 截图或口头说。AI 说绿 ≠ 真绿，你跑一遍就知。

② 启动 app 探活（确认真能跑起来）

形态 A：H2 默认（最快，零依赖）

.\mvnw.cmd spring-boot:run

等约 10–20 秒，出现 Started MockInterviewApplication 即起好。浏览器开：

http://localhost:8080/api/health/deps

应看到 {"database":{"ok":true,...},"redis":{"ok":false,...}}。H2 内存库恒连 → database.ok:true 即 PASS；Redis 没起 → redis.ok:false 是本地预期，不算挂。

形态 B：mysql 真库（生产口径，必须做一遍）

docker compose up -d
$env:SPRING_PROFILES_ACTIVE="mysql"; .\mvnw.cmd spring-boot:run

再开 /api/health/deps，这次 database 与 redis 必须都 ok:true 才叫真环境就绪。

判据： 两套形态都能起、都能进主界面 = 双形态 PASS。只验 H2 不算完。

③ 浏览器点一遍（E2E，AI 替不了的真实点击）

保持 ② 的 app 在跑，浏览器开 http://localhost:8080。

通用走查（每次都点）

  1. 注册一个用户（填用户名 + 密码）→ 登录。R1-1.5 已做登录面板，登录后应进主界面，不再弹 401。
  2. 左侧贴一段 JD → 上传一份简历 → 勾角色（技术深挖官）→ 点 开始模拟面试。
  3. 中间栏题目自己流出来（SSE 推流）→ 在回答框输入文字 → 提交。
  4. 看到评分 / 追问 → 点 结束 → 右侧出 Critic 报告（四段讲解）。
怎么判断"双令牌通了"： 你不用看代码。只要流程能走通（题目能出、能提交、报告能出）就说明 JWT + vaultToken 双令牌链路通了。一旦卡 401（页面弹登录框 / 红字），就是令牌没带对。

④ 读 diff 防夹带（两步命令）

git log --oneline master..HEAD
git diff --stat master...HEAD

对照 docs/tasks.md 里这个 task 的"验收标准"：

  • 改的文件是否只围绕本 task？（如 R1-2 应是实体 @Index + 迁移脚本 + Repository）
  • 如果出现不相干的重构 / 大文件改动 / 一堆 doc → 直接问 AI："这笔提交里 XXX 是干嘛的？"
  • 本次 Trea 的 9ef7f88 把 R1-1.5 前端 + R1-2 后端 + 多个 doc 混进一笔提交——这种"粒度混装"你可以要求它拆细再 merge。
