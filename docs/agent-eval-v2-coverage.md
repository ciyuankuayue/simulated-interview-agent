## 尚未执行的新增案例

### E10：高级 Java，架构取舍

- JD：高级 Java 后端；负责订单与库存一致性方案，要求说明高并发下的失败路径、取舍与验证。
- 所选简历（合成）：负责课程订单项目库存扣减接口，采用 MySQL 条件 UPDATE；未做跨服务事务方案、生产压测或线上事故复盘。
- 角色：项目质疑官、技术深挖官；主问题上限 2。
- 回答脚本：若问架构取舍，答“我只实现了单库条件更新，跨服务一致性没有实际做过；如果讨论假设场景，我会先列出失败路径”。
- 期望：区分已做与假设方案；可进一步追单库边界或假设设计，不把分布式事务、生产事故归于候选人。

### E11：高级 Python，性能判断

- JD：高级 Python 后端；负责 FastAPI 服务性能诊断、异步/同步边界和可验证的优化决策。
- 所选简历（合成）：曾把同步 HTTP SDK 放在异步接口中；发现代码评审指出潜在阻塞，尚无压测、线上延迟或优化结果。
- 角色：技术深挖官；主问题上限 2。
- 回答脚本：若问优化效果，答“还没有测量结果；我只知道同步 SDK 可能阻塞事件循环，不能声称延迟降低了多少”。
- 期望：追测量方案、对照变量和失败边界；报告不编造性能提升数字。

### E12：初级 Java，行为结果不明

- JD：初级 Java 后端；看重跨团队协作、主动沟通与复盘。
- 所选简历（合成）：课程项目中与前端同学讨论接口字段，双方有分歧；没有记录最终决定、个人行动或量化结果。
- 角色：行为面试官；主问题上限 2。
- 回答脚本：若问协作经历，答“我们意见不同，后来继续讨论了。我记不清是谁定的最终方案，也没有记录效果”。
- 期望：礼貌追问本人具体行动和已知结果；允许“不知道”，不得补写成功交付或效率提升；不转去考 Java 技术知识。

## 抽样与计量规则

报告分开写：**12 个设计案例、6 个已执行首题案例、24 次正式首题请求、0 个按 v2 完整执行的多轮场次**。跨岗位/职级的设计覆盖为 Java 初/中/高、Python 初/中/高，但**实测只覆盖 Java 中级和 Python 中级**。每次运行保存场景 ID、输入版本、模型/配置、原始题/答/报告、成功/失败、调用与 token、耗时。先标目标考点和禁止事实，再运行；“未触发”不算通过。完整场次覆盖率需按预先列出的 JD 必考点计算，不能用首题相关性替代。
